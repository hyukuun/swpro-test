# 정답 획 데이터 (`data/extracted/<폰트 id>/`)

폰트 파일(`data/fonts/<폰트 id>.ttf`, 기본 `NotoSansKR-Light.ttf`)에서 정답 획을 만든 결과가 폰트 id 폴더 하나에 들어 있다.
폰트 id는 폰트 파일 이름에서 확장자를 뺀 것이다. 아래 숫자는 `NotoSansKR-Light` 기준이다.

**최종 결과는 정답 획 사전 `composed_all.json`이다** (11,172자 + 자모 단독 51개).
서버(`app/core/reference.py`)는 이 파일만 읽는다. 나머지 파일은 이 파일을 만드는 재료이거나 만들다 생긴 기록이다.

## 전체 순서

| 순서 | 프로그램 | 하는 일 | 언제 |
|---|---|---|---|
| 1 | `extract.py` | 폰트 → 재료 (자모 모양 + 자모가 놓일 자리) | 폰트를 바꾸거나 추출 방식을 고칠 때만 |
| 2 | `editor.py` | 사람이 점을 옮겨 고침 → `tweaks.json` | 필요할 때만 |
| 3 | `compose.py --all` | 재료 + 조정으로 조립 → `composed_all.json` | **1·2를 했으면 반드시 다시** |

1·2를 하고 3을 안 하면 서버 정답은 그대로다 (오류는 나지 않아서 놓치기 쉽다).
`compose.py`를 `--all` 없이 실행하면 확인용 그림(`outputs/compose.png`)만 만들고 서버에는 영향이 없다.

## 조립 방법 (`compose("뒁")`)

뒁 = ㄷ + ㅝ + ㅇ 으로 나누고, 자모마다:

1. **칸 배치**: 그 자모가 들어갈 자리 상자를 찾는다 (`slots.json`, 예: "받침 있는 ㅝ 글자의 초성 자리").
2. **세부**: 자모 안 부품·획 위치까지 맞출지 정해 그 상자를 쓴다 (`detail.json`, `box_mode.json`).
3. **수동 조정**: editor로 옮긴 만큼 점을 더 옮긴다 (`tweaks.json`).

그리고 자모 모양(`jamo_strokes.json`)을 그 상자 크기에 맞춰 넣는다.

- 자리 상자는 글자별이 아니라 **"자리 유형"별**(예: `cho|ㅗ|1` = ㅗ이고 받침 있는 글자의 초성)이라,
  완성형 2,350자에서 잰 값으로 11,172자를 모두 조립한다. 예: "똠"은 2,350자에 없지만 곰·봄에서 잰 자리를 쓴다.
- 표본이 적은 자리는 대표 상자(세로·가로·복합 모음별)로 대신한다. 그래서 실패하는 글자가 없다.
- 자모 단독(ㄱ, ㅏ …)은 `compose_jamo()`: 그 폰트의 자모 글자가 차지하는 상자에 자모 모양을 넣는다.

## 수동 조정이 반영되는 방식 (`tweaks.json`)

editor에서 저장하면 이동량이 두 종류로 저장된다.

- `slot`: **같은 자리 전체**. 예: `jung|ㅝ|1` = 받침 있는 ㅝ 글자 모두의 ㅝ.
- `syllable`: **그 글자 하나만**. 예: "뒁"의 5번째 획.

조립할 때 획마다 두 키를 찾아, 있으면 이동량을 더한다 (둘 다 있으면 둘 다).
측정값(1·2) 위에 더하는 방식이라 extract를 다시 해도 조정은 남는다.

## 폰트 정보

이름, upm, 글자 상자 위 `em_top`은 파일로 두지 않고 폰트 파일에서 바로 읽는다.
`em_top`이 틀리면 추출이 깨진다(874가 들어갔을 때 ㅚ 추출이 실패했다). 자동 추정이 틀린 폰트는 `extract --em-top <값>`으로 지정한다.

## 공통 규칙

- **좌표**: 0~1로 정규화했다. 원점은 왼쪽 위이고, x는 오른쪽, y는 아래로 갈수록 커진다.
- **기준 틀 (글자 프레임)**: 폰트의 글자 상자(em box) 전체가 0~1이다.
  - Noto는 폰트 단위 x 0~1000, y 880(위)~-120(아래)이 0~1에 대응한다.
  - 그래서 글자는 상자 가장자리에 붙지 않고 여백을 두고 그려진다.
  - 예외: `jamo_strokes.json`은 자모 하나 크기 기준이라 틀이 다르다.
- **획**: 한 획마다 점 32개(`points`)를 찍는다. 점은 획이 시작하는 곳부터 쓰는 방향으로 같은 간격으로 놓인다.
- **role**: `cho` 초성 / `jung` 중성 / `jong` 종성
- **order**: 글자 안에서 몇 번째로 쓰는 획인지. 1부터 센다.

## 파일별 설명

| 파일 | 내용 | 만드는 단계 | 크기 (Noto) |
|---|---|---|---|
| `jamo_strokes.json` | 자모 51개의 획 | jamo | 51자모, 180획 |
| `strokes_ksx1001.json` | 음절 글리프에서 직접 뽑은 획 (측정 재료) | syllables | 2,283자 |
| `slots.json` | 자리별 자모 상자 (① 칸 배치) | table | 키 182개 |
| `detail.json` | 자모 안 부품·획 상자 (② 세부) | table | 키 2,495개 |
| `box_mode.json` | 자모마다 어떤 상자를 쓸지 | mode | 51자모 |
| `tweaks.json` | 사람이 손으로 옮긴 점 (③ 수동 조정) | `editor.py` | 있을 때만 |
| `composed_all.json` | **정답 획 사전** (11,172자 + 자모 단독 51개) | `compose --all` | 11,223자, 약 68MB |

### `jamo_strokes.json`: 자모 51개의 획

자모 하나만 있는 글리프(ㄱ, ㅏ, ㅘ, ㄼ …)에서 뽑았다. 모두 눈으로 검증했다.

```json
{"ㄱ": [{"order": 1, "unit": "p0", "dirs": ["E", "S|SW"], "points": [[0.0, 0.0095], ... 32점]}]}
```
- **좌표 틀이 다르다.** 글자 프레임이 아니라 자모 자신의 상자 기준 0~1이다. 조합할 때 이 모양을 자리 상자에 맞춰 늘이거나 줄인다.
  - ㅡ처럼 높이가 거의 없는 자모는 그 축을 0.5로 둔다. ㅣ처럼 너비가 거의 없는 자모도 같다.
- `unit`: 부품 번호. 겹자모는 앞 부품이 `p0`, 뒤 부품이 `p1`이다. 예: ㅘ = ㅗ(p0) + ㅏ(p1).
- `dirs`: 그 획의 획순 템플릿 방향. 예: `["E", "S|SW"]`는 오른쪽으로 간 뒤 아래나 왼쪽 아래로 꺾는다는 뜻이다.

### `strokes_ksx1001.json`: 음절에서 직접 뽑은 획 (측정 재료)

완성형 음절 글리프를 직접 쪼개 뽑은 결과다. **정답으로 쓰지 않는다.** 이 데이터로 "자모가 음절 안 어디에 놓이는지"를 잰다.

```json
{"가": {"pass": 1, "strokes": [{"order": 1, "jamo": "ㄱ", "role": "cho", "points": [... 32점]}, ...]}}
```
- `pass`: `1`이면 정상 탐색으로 찾은 것, `2`이면 느슨한 탐색으로 찾은 것이라 틀릴 가능성이 높다. 측정에는 pass 1만 쓴다.
- 획순이 틀리게 뽑힌 글자가 섞여 있다. 측정할 때 배치 원칙을 어기는 글자는 걸러내고, 상자는 중앙값으로 잡아서 영향을 줄인다.

### `slots.json`: ① 칸 배치 (자리별 자모 상자)

음절 안 각 자리에 자모가 들어갈 상자다. `strokes_ksx1001.json`에서 같은 자리끼리 상자를 모아 중앙값을 냈다.

```json
{"cho|ㅏ|0": {"box": [x0, y0, x1, y1], "n": 표본 수}}
```
| 키 형식 | 뜻 | 예 |
|---|---|---|
| `cho\|<중성>\|<받침 0/1>` | 초성 자리 | `cho\|ㅏ\|0` = 받침 없는 ㅏ 글자의 초성 |
| `jung\|<중성>\|<받침 0/1>` | 중성 자리 | `jung\|ㅝ\|1` = 받침 있는 ㅝ |
| `jong\|<모음방향>\|<종성>` | 종성 자리 | `jong\|V\|ㄴ` |
| `…\|V/H/C\|…`, `jong\|<방향>\|*` | 표본이 적을 때 쓰는 일반 상자 | `cho\|H\|0` |
| `jong\|+\|<종성>` | 받침별 보정값 (일반 상자에 더함) | `jong\|+\|ㄵ` |

- 모음방향: `V` 세로(ㅏㅓㅣ…), `H` 가로(ㅗㅜㅡ…), `C` 복합(ㅘㅝㅢ…)
- `box`: 글자 프레임 0~1. 보정값(`jong|+|…`) 키만 상자가 아니라 더할 차이값이다.

### `detail.json`: ② 세부 (자모 안 부품·획 상자)

같은 자리라도 자모 안 획 간격은 폰트마다 다르다. 이를 맞추려고 부품별, 획별 상자를 따로 잰 것이다.

```json
{"jung|ㅝ|1|s2": {"box": [x0, y0, x1, y1], "n": 표본 수}}
```
- `<자리>|p<번호>`: 부품 상자. 예: `jung|ㅘ|1|p0` = 받침 있는 ㅘ의 ㅗ 부분.
- `<자리>|s<번호>`: 획 상자. 예: `jung|ㅝ|1|s2` = 받침 있는 ㅝ의 세 번째 획.
- 초성 자리 키에는 자음을 붙인다. 예: `cho|ㅏ|0|ㅂ|s2`
- 표본(`n`)이 3개 미만이면 조합할 때 쓰지 않는다. 그때는 ①의 자모 상자로 돌아간다.

### `box_mode.json`: 자모마다 상자 방식

```json
{"ㅢ": "piece", "ㅝ": "stroke", "ㅡ": "jamo", ...}
```
- `jamo`: 자모 전체를 상자 하나(①)에 넣는다.
- `piece`: 부품마다 상자(②)를 쓴다.
- `stroke`: 획마다 상자(②)를 쓴다.
- 세 방식 중 실제 음절 모양에 가장 가까운 것을 자동으로 골랐다(교차 검증). 촘촘한 방식은 5% 이상 나을 때만 고른다.

### `composed_all.json`: 정답 획 사전

음절은 `jamo_strokes`의 모양을 `slots`, `detail`, `box_mode`에 따라 음절 안에 배치하고, `tweaks`가 있으면 손 조정을 더한 결과다.
자모 단독(ㄱ, ㅏ, ㅘ, ㄳ …)은 `jamo_strokes` 모양을 그 폰트의 자모 글리프 상자에 맞춰 놓았다
(role: 자음 `cho`, 모음 `jung`, 겹받침 `jong`).
**교정 엔진은 `core/reference.py`의 `get_reference(글자)`로 여기서 꺼내 쓴다.**

```json
{"가": [{"order": 1, "jamo": "ㄱ", "role": "cho", "points": [[0.0996, 0.1752], ... 32점]},
        {"order": 2, "jamo": "ㅏ", "role": "jung", "points": [...]},
        {"order": 3, "jamo": "ㅏ", "role": "jung", "points": [...]}]}
```
- 현대 한글 11,172자 모두 실패 없이 들어 있다. 획은 초성 → 중성 → 종성 순서이며, 각 자모 안에서는 획순 템플릿 순서를 따른다.
- 형식은 팀 합의 전 초안이다.

### `tweaks.json`: ③ 수동 조정 (있을 때만)

`app/core/stroke_vectorizer/editor.py`에서 점을 끌어 옮기면 저장된다. 측정을 다시 해도 이 파일의 조정은 그대로 남는다.

```json
{"slot":     {"jung|ㅝ|1": {"2": [[dx, dy], ... 32개]}},
 "syllable": {"뒁": {"5": [[dx, dy], ... 32개]}}}
```
- `slot`: 같은 자리 전체에 적용한다. 키는 자리 id이고, 그 안의 번호는 자모 안 획 번호(0부터)다.
- `syllable`: 그 글자 하나에만 적용한다. 그 안의 번호는 `order`다.

## 다시 만들기

```bash
python -m app.core.stroke_vectorizer.extract                              # 기본 폰트 전부 (약 30초)
python -m app.core.stroke_vectorizer.extract --steps table,mode            # 배치표만 다시
python -m app.core.stroke_vectorizer.compose --all                         # 정답 획 사전 composed_all.json (약 15초)
```
